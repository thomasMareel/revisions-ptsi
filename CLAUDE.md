# CLAUDE.md — Conventions du projet « Révisions PTSI »

Notes destinées à Claude pour les sessions futures. Objectif du projet : rendre maintenable un fichier de révisions PTSI et l'héberger sur GitHub Pages, **sans casser l'existant**.

## Règles de collaboration

- **Tout en français** (réponses, commentaires, contenu).
- **Ne rien casser** de ce qui marche (design + fonctionnalités). Pas de refonte non demandée (la refonte graphique « Cahier de prépa » d'octobre 2026 a été demandée et sa conception validée : voir « Identité visuelle »).
- **Modifications du HTML autorisées sans confirmation préalable** (accord donné par l'utilisateur le 2026-09-26) : agir directement, puis expliquer ce qui a été fait.
- L'utilisateur est étudiant en prépa, débutant en dev. Privilégier des explications claires et des changements incrémentaux.
- **Mise en ligne systématique (consigne de l'utilisateur du 2026-10-05)** : **chaque tâche terminée est publiée sur `main` sans demander la permission**, petits correctifs comme gros changements. Avant de pousser : `validate.py`, `check_js.py`, suites de tests concernées (batterie complète pour un gros changement), bump de `CACHE_VERSION` si un asset change ; pour un gros changement, créer d'abord un point de retour (branche `sauvegarde-avant-…` sur l'état actuel de `main`). Ensuite : vérifier que le run Actions est `completed success`, et dire à l'utilisateur ce qui est en ligne. Ne jamais pousser un travail inachevé ou dont les tests échouent.
- **Contenus de 2ᵉ année (PT spé)** : rédigés à partir des manuels privés du dépôt `thomasMareel/cours-pt-spe` (release v1), qui ne servent qu'à cerner le programme et les notations. **Rédaction originale obligatoire** (site public, droit d'auteur) : ne jamais recopier ni paraphraser de près leurs phrases, énoncés, corrigés, exemples chiffrés, schémas ou plans ; exercices inventés.

## Architecture

- **Un seul fichier servi : `index.html`** (≈ 78 300 lignes, ≈ 6,5 Mo). HTML + CSS + JS tout inline : **18 blocs `<script>` inline** (+ `vendor/mathjax/tex-mml-chtml.js`) : 5 petits avant (thème du `<head>`, config MathJax, `__icon`, Lorentz, `cstCards`), **un grand script applicatif unique** (de `const Store = (function` à la navigation, au routage, à la recherche et à l'impression), puis 12 modules : toasts, Bilan, Formulaire, préc./suiv., lien d'évitement + calcul mental + badges des révisions du jour + taille du texte, menus de l'en-tête, accessibilité (`.reveal` au clavier, focus des overlays), **CONTENU**, cartes signalées, Aujourd'hui, **PAGE CHAPITRE**, enregistrement du service worker. Les raccourcis globaux et leur aide (`#key-help-modal`) sont dans le grand script. Une exception non rattrapée dans le grand script coupe tout ce qui suit (decks, navigation, quiz, tiroir) : code de chargement défensif (`if(!el) return;`), modules enveloppés (`try/catch`, `sur(f)`).
- **Ne jamais lire `index.html` en entier** ni se fier à des numéros de ligne : chercher par **ancre grep** (`grep -n 'const CHAPTERS = \['`, puis `sed -n 'A,Bp'`). Régions du CSS : `grep -n 'RÉGION' index.html` ; titres de blocs : `/* =====`, `/* ---`.
- `fichier de départ/` = original intact, **non versionné** (voir `.gitignore`).
- Aucun build. Édition directe du fichier. Autour : `sw.js` + `manifest.webmanifest` (PWA), `vendor/`, `tools/`, `tests/` + `package.json` (tests navigateur), `docs/audit-2026-09.md` (audit de référence : carte du fichier, anomalies, pistes), `docs/refonte/` (conception de la refonte graphique : `conception/SPEC.md`, `tokens.css`, `composants.css`, maquettes et captures cibles ; `travail/regions.md` : propriétaires des régions CSS ; `REPRISE.md`).

### Pilotage data-driven

Le tableau **`CHAPTERS`** (`grep -n 'const CHAPTERS = \['`) est la source de vérité : navigation, redraw des simulateurs, recherche, quiz, tiroir en dérivent. **160 chapitres** : physique 50, maths 48, SI 36, info 8, anglais 18 (dont 52 de 2ᵉ année). Chaque entrée (11 champs) :

```js
{ id:'rlc', prefix:'rlc', name:'Circuit RLC série',
  matiere:'physique', sub:'ondes', subLabel:'Ondes & signaux', domain:'ondes',
  matiereLabel:'Électrocinétique',
  panels:['cours','meth','simu','flash','exos'], drawFn:'drawSim',
  mobLabel:'Circuit RLC série' }
```

- `matiere` ∈ `physique` | `maths` | `si` | `info` | `anglais`. Les chapitres `physique/maths/info/anglais` vivent dans le grand `<main>` ; `si` a son propre `<main id="si-content">` (masqué au départ).
- **Ajouter une matière** = l'ajouter aux énumérations en dur : intercalaires `.mob-mat-btn.mat-tab` de la navigation (HTML), zone `.mat-content[data-mat-content="X"]`, `buildSidebars` (`['physique',…]`), `buildChapData` + `const MATS` (navigation), les **8 tables de noms** `{ physique:'Physique', … }` (`grep -n "physique:'Physique'"` : fiche de révision `FLASH_MAT_NOMS`, recherche, impression, navigation, Bilan, cartes signalées, Aujourd'hui, PAGE CHAPITRE), `NOMS`/`MATS` d'Aujourd'hui, puce `qc-<matière>` (avec `data-mat`) du quiz (HTML + listes JS : `grep -n 'qc-physique'`), `perMat` du **Bilan**, jetons `[data-mat="X"]` (région JETONS, bloc clair **et** bloc sombre, **et** leur copie du filet de sécurité Auto), variable `--<matière>` (+ `-fond`, `-vif`). Les couleurs viennent toutes des jetons `data-mat` (plus de `colorsMap` ; `.flash-mat-*`, `.quiz-chapter-badge.*`, `.mt-*` ne sont plus stylés).
- **Anglais** : matière de langue, cartes en **texte brut**. `makeFlash` détecte `CHAPTERS_BY_PREFIX[prefix].matiere === 'anglais'` (`isPlainDeck`) et rend `card.q`/`card.a` en HTML brut sans `flashPretty` (sinon « I », « / » seraient mathématisés) ; idem quiz (`item.meta.mat === 'anglais'`). Réponses avec `<strong>`/`<em>`/`<br>` possibles. Panels typiques : `['cours','flash']`. **Lecture audio (TTS)** : `window.__TTS` (Web Speech API, défini AVANT les decks car `makeFlash` teste `__TTS.ok`) — bouton 🔊 dans l'en-tête de la fiche des cartes anglaises et dans le quiz (`#quiz-tts-btn`) ; lit la face visible (voix en-GB/fr-FR, gloses françaises retirées), stoppée au flip/changement/fermeture. Les decks **info**, eux, passent par `flashPretty` (anomalie connue).
- `drawFn` : fonction du simulateur (27 chapitres), ou `null`. Le simulateur SVG de Lorentz (`lorDraw`, `lor-simu`) n'est **pas** déclaré dans `CHAPTERS`.
- `CHAPTERS_BY_ID` / `CHAPTERS_BY_PREFIX` sont dérivés automatiquement (après le tri).
- `validateChaptersCoherence()` (IIFE) alerte dans la console au chargement, mais ne compare que les ids de chapitre (`CHAPTERS` ↔ `div.chapter`).

### Ordre d'apprentissage (réorganisation centralisée)

Juste après `CHAPTERS`, l'IIFE `reorderChapters` déclare **`CHAP_GROUPS`** (`grep -n 'const CHAP_GROUPS'`) = `[ [subCode, subLabel, [ids…]] , … ]` (25 groupes, dont `['ia', 'Intelligence artificielle', ['ia']]` en SI, après Capteurs) : **source unique** de l'ordre pédagogique, des **sous-domaines** (`c.sub`) et de leurs **libellés** (`c.subLabel`), qu'il réécrit en réordonnant `CHAPTERS` en place. `subCode` à `null` = pas de code de sous-domaine (maths ; le `subLabel` groupe quand même le tiroir). Un `id` absent est rejeté en fin de liste. **Pour changer l'ordre ou le sous-domaine : éditer `CHAP_GROUPS`**. ⚠️ `matiereLabel` (tag) et `domain` (`data-domain`, alias de compatibilité) ne sont **pas** réécrits : les tenir à la main en cohérence (ex. `lorentz` porte encore le tag « Mécanique » dans le groupe Électromagnétisme). Tags ajoutés avec la PT spé : « Électronique » (ali, oscelec, signum, groupe Ondes & signaux), « Résistance des matériaux » et « Conception » (SI Mécanique), « Intelligence artificielle » (ia) ; le chapitre SI `ia` a `domain:'info'`. Le code `'meca'` sert en physique ET en SI. Les couleurs ne dépendent plus de `domain` mais de `matiere` (`data-mat`).

**2ᵉ année** : dans la même IIFE, `window.__YEAR2A = new Set([...])` (52 ids : maths 28, physique 13, SI 11 ; les 26 chapitres de PT spé ajoutés le 2026-10-04 sont listés en fin de `CHAPTERS`, de `__YEAR2A` et des decks, sous un commentaire « PT spé (2ᵉ année) ») pilote le badge d'année de l'intercalaire (`.ctb-meta`), le « 2A » des rangées de la navigation, le `data-year` des `.chap-btn`, le filtre d'année de la navigation (clé `year`) et le surtitre de la page de garde imprimée (« PT · 2ᵉ année »). Règle en dur (`buildChapData`, `syncSidebar`) : **anglais** et `constantes` sont visibles les deux années. Juste après `__YEAR2A`, la même règle est exposée : `window.__chapYear(c)` (0 = les deux années, sinon 1 ou 2), `window.__currentYear()` (clé `year`, 1 par défaut) et `window.__inYear(c, y)`. Elles filtrent par année **préc./suiv.** (`goRelChapter`/`updateNavButtons`, touches n/p, Alt+←/→ : année du chapitre actif, ou année courante pour anglais/constantes). Le **Bilan** et le **quiz** (`buildDeck`) passent par `window.__inRevision(c, y)` : en 1ʳᵉ année, 1ʳᵉ année seulement ; en 2ᵉ année, **les deux années** (les concours portent sur tout le programme). Les « Révisions du jour » (`dueDeck`) restent toutes années. En 2ᵉ année, ouvrir un chapitre de 1ʳᵉ année depuis la navigation **garde** la 2ᵉ année (sa partie se déplie).

### Navigation : barres invisibles = couche de commande

Les `.mat-content` du HTML ne contiennent que des conteneurs vides `.subdomain-bar` / `.chapter-bar` (en maths, la div **est** `.chapter-bar mat-content` ; la zone SI précède `main#si-content`). `buildSidebars` les remplit de `.sub-btn` / `.chap-btn` depuis `CHAPTERS` (tag = `matiereLabel`, libellé = `mobLabel`), **avant** l'attachement des handlers. Ces barres sont **invisibles à toutes les largeurs** (`display:none !important`) : `.chap-btn`/`.tab` forment une **couche de commande cachée**, cliquée par `navigateTo`, la navigation, le routage et préc./suiv. La seule navigation visible est **`#mob-drawer`** : **barre latérale permanente** de 288 px à partir de 1200 px (repliée / affichée par `#nav-toggle-btn`, clé `navCollapsed`, classe `html.nav-replie`), **tiroir** de 320 px de 768 à 1199 px (`#nav-toggle-btn`), **page plein écran « Chapitres »** au téléphone (☰ `#mob-menu-btn`). Le sommaire de la matière, les deux `<main>`, `#chap-rail`, `#chap-pager` et le pied sont enveloppés dans **`<article id="app-main" role="none">`** (colonne de lecture, décalée par la barre latérale) : jamais un `<div>` ni un `<section>` englobant, que les `</div>` / `</section>` orphelins du contenu refermeraient (les chapitres sortiraient du `<main>`). **Seul le handler `.chap-btn`** (`grep -n 'CHAPTER SWITCHING'`) bascule entre le `<main>` principal et `#si-content`.

→ Naviguer **toujours** via `navigateTo('chap-<id>','<prefix>-<onglet>', cb)` ou un clic sur `.chap-btn`/`.tab`, jamais en posant `.active` à la main. Ne pas supprimer ces barres, et **ne pas ajouter de `.chap-btn` dans le HTML** (effacés par `buildSidebars`).

**Ajouter un chapitre = 5 endroits** (gabarit : `GABARIT-CHAPITRE.md`) : (1) entrée `CHAPTERS` ; (2) id dans `CHAP_GROUPS` ; (3) id dans `__YEAR2A` si 2ᵉ année ; (4) bloc DOM `chap-<id>` dans le bon `<main>` ; (5) `const <prefix>Cards` + `makeFlash(...)` **après** les constantes `FLASH_*` (`grep -n 'const FLASH_FR2'` ; avant, TDZ → plantage).

### Routage par URL (deep-link + bouton précédent)

L'IIFE `urlRouting` synchronise `location.hash` (`#chapId/onglet`, ex. `#rlc/cours`) avec le chapitre/onglet actif, par **délégation** (clics sur `.chap-btn`/`.tab`/`.sub-btn`/`.mob-chap-item`/boutons matière, puis `syncHash`, exposé en `window.__syncHash`). `pushState` au changement de chapitre (le bouton « précédent » revient au chapitre précédent), `replaceState` au simple changement d'onglet. Au chargement (restauration à +120 ms), un `#hash` a priorité sur `lastPos` (`window.__navFromHash`). `popstate` rejoue la navigation. **Sommaire de la matière** : `#sommaire/<matière>` (`window.__ouvrirSommaire(mat)`, `__fermerSommaire()`, `__sommaireOuvert()` ; 2ᵉ clic sur l'intercalaire actif de la navigation, lien « matière » du fil d'Ariane de l'intercalaire ; fermé par tout clic `.chap-btn`). **Retour Android** : au téléphone, une page plein écran ouverte (page Chapitres, feuille ⋯, Aujourd'hui, recherche, quiz, Bilan, fenêtres : liste `PAGES` de `urlRouting`) empile une entrée d'historique fictive (même URL) que « précédent » referme ; fermée autrement, l'entrée est retirée (`history.back`, popstate ignoré, garde-fou sur `history.state` : on ne recule jamais hors du site) ; un chapitre choisi depuis la page la **remplace** (`window.__consommerPageFictive()` avant le clic `.chap-btn`).

## Conventions de nommage des IDs (IMPORTANT)

- Le `<div>` du chapitre : `id="chap-<id>"` (ex. `chap-rlc`).
- **`id` ≠ `prefix`** pour **141 chapitres sur 160** : le `prefix` sert aux panels et aux flashcards.
  Ex. chapitre `id:'ondes'` → panels `ond-` ; `id:'rlc'` → panels `rlc-`. **Construire un id de panneau avec `CHAPTERS_BY_ID[id].prefix`**, jamais `id+'-cours'`.
- Panels : `<section class="panel" id="<prefix>-<panel>">` avec `<panel>` ∈ `cours` | `meth` | `simu` | `flash` | `exos`.
- Onglets : `<button class="tab" data-panel="<prefix>-<panel>">`.
- Bouton de commande (généré, invisible) : `<button class="chap-btn" data-chap="<id>">`.
- Les IDs du chrome (`#search-btn`, `#study-btn`, `#theme-btn`, `#more-btn`, `#mob-*`, overlays…) sont lus par le JS **et** par les tests : les garder.

## Structure d'un chapitre (DOM)

```html
<div class="chapter" id="chap-<id>">
  <nav class="tabs">
    <button class="tab active" data-panel="<prefix>-cours"><span class="num">01</span>Cours</button>
    <button class="tab" data-panel="<prefix>-meth">…Méthodes</button>
    <!-- simu seulement si drawFn défini -->
    <button class="tab" data-panel="<prefix>-flash">…Flashcards</button>
    <button class="tab" data-panel="<prefix>-exos">…Exercices</button>
  </nav>
  <section class="panel active" id="<prefix>-cours"> … </section>
  <section class="panel" id="<prefix>-meth"> … </section>
  …
</div>
```

Le HTML source garde cette forme (les `<span class="num">01</span>` restent mais sont **masqués** ; le libellé affiché est réécrit par le module PAGE CHAPITRE : « Cartes » pour Flashcards, « Simu » / « Exos » au téléphone). Classes de contenu : `.course-section`, `.sec-num` (ex. « §1 · LES BASES »), `.intro`, `.formula` (formules MathJax `$$…$$`, attribut facultatif `data-nom`), `.def-box`, `.prop-box`, `.method-box` (étapes `<span class="step">`), `.notice`, `.reveal` (bloc dépliable au clic). Exercices : `.exo` **dans** `.exo-wrapper` (exo « CONCOURS PT » `.exo.concours` compris, sans `</div>` en plus). Détail des rendus : « Contenu » ci-dessous et `GABARIT-CHAPITRE.md`.

**Page chapitre** (région PAGE + module « PAGE CHAPITRE », `<script>` juste avant l'enregistrement du service worker ; SPEC §4.4) : la **feuille** est le `.chapter` lui-même (`--sheet`, rayon, ombre, liseré `--chap-vif` ; `overflow:clip`, jamais `hidden` : les onglets collent). `injectChapterTitleBanners` ne crée que l'**intercalaire** `.chap-title-banner[data-mat]` + `h2.ctb-title` ; le module l'enrichit **paresseusement** au 1ᵉʳ affichage du chapitre (`data-enrichi`) : fil d'Ariane `.ctb-crumb` (matière → `__ouvrirSommaire`, partie → `window.__montrerPartie(mat, sub)` de la navigation, tag `matiereLabel`), actions `.ctb-actions [data-ctb]` (Formulaire → `openFormulaSheet`, Imprimer → `printChapter`, Épingler → `__togglePin`), méta `.ctb-meta` (badge d'année, sections, cartes, exercices, simulateur). Titres de section en casse de phrase : `window.__casPhrase(texte, section)` (noms propres et sigles gardés). **Onglets** (enrichis de même) : `role=tablist/tab/tabpanel`, `aria-selected`, tabindex itinérant, ← → Début Fin ; libellé `.tab-l` (« Cartes » ; `.tab-long[data-court]` + `.tab-court` : « Simu », « Exos » au téléphone), effectifs `.cnt`, cartes dues `.count` (`window.__majPageCompteurs`, appelé par `__updateReviseBadge`) ; « 01–05 » (`.num`) masqués. Collants sous l'en-tête, fond plein + ombre quand ils collent (`.onglets-colles`, IntersectionObserver sur l'intercalaire) ; au téléphone, pas d'intercalaire, onglets sous `.mbar` (`top:0` avec `html.mbar-cachee`). `data-onglet` (onglet actif) sur la feuille : Exercices et Simulateur alignés sur le bord de la feuille (retrait 2,5rem), Simulateur élargi (66rem) et sans rail. Panneaux Cours/Méthodes sans retrait gauche (grille marge | texte de `.course-section`, région CONTENU), filet rouge `--marge` en `::before` (≥ 1024 px). **Rail droit** `aside#chap-rail` (≥ 1 360 px, `position:fixed`, `html.rail-on` → `#app-main{padding-right:var(--rail-w)}`), reconstruit pour le chapitre affiché : sommaire `.toc` « Dans ce chapitre » (onglets autres qu'Exercices), « Mes cartes » `.rail-cartes` (LECTURE SEULE de `flash:<prefix>` ; bouton → `quizStartDue(prefix)`), liste des exercices `.exo-list` sur l'onglet Exercices (exercice visible suivi, titres coupés à 2 lignes avec le titre complet en infobulle, filtres `.filtre-masque` respectés). **Pied** `#chap-pager` (deux cartes précédent / suivant, noms complets, le long du filet rouge) déplacé en fin du chapitre affiché.

**Deux `.chapter.active` dans le HTML source** : `chap-rlc` et `chap-ingsys` (un par `<main>`), jusqu'au 1ᵉʳ clic `.chap-btn` (restauration à +120 ms s'il y a un `#hash` ou un `lastPos` ; sinon, à la 1ʳᵉ visite, jusqu'à la 1ʳᵉ navigation). Pour le chapitre **visible**, filtrer par `offsetParent` (cf. `function activeChapter` du formulaire).

### Contenu (région CONTENU + module « CONTENU », SPEC §5.2, §5.3, §7.2, §7.3)

Le module `CONTENU` (`grep -n '===== CONTENU : enrichissements'`, `<script>` après le module d'accessibilité) est **paresseux et idempotent** : un panneau n'est traité qu'à son 1ᵉʳ affichage (`typesetPanel` appelle `window.__contenuPanneau(panel)`), le reste après le rendu MathJax (`window.__apresRendu(racine)`, appelé dans la promesse de `typesetPanel`, de `toggleSol`, du Formulaire et du rendu de démarrage ; rattrapage à l'initialisation des panneaux déjà rendus si la restauration à +120 ms a précédé la lecture du module). Il ne modifie jamais le texte lu par la recherche, le sommaire ou l'impression (`textContent` des `.sec-num` inchangé).
- **Surtitre** `.sec-num` « §1 · LES BASES » → `span.sec-n` « §1 » (dans la marge à l'ordinateur) + `span.sr` « · » + `span.sec-t` (classe `.coupe`) ; un surtitre sans « §n » (« MÉTHODES · RLC ») reste simple.
- **Typographie** (hors `code/pre/kbd/mjx-container`) : espace fine insécable avant ; ! ?, insécable avant : et », après « ; ponctuation collée à sa formule (`.mj-colle`) ; formule en ligne plus large que sa ligne → `.mj-large` (défile dans la ligne au lieu d'élargir la page).
- **Formules en bloc** `.formula` : creux discret, centrées, **défilement horizontal** si trop longues (plus aucun débordement à 390 px : `DEBORDEMENTS_CONNUS` est vide) ; formules consécutives fusionnées en un bloc (`:has`) ; `data-nom="…"` = nom de la formule (dans la marge à l'ordinateur, au-dessus au téléphone ; repris par le Formulaire et la recherche).
- **Encadrés** : intitulés **générés en CSS** (ne pas les écrire dans le HTML) — `.def-box` « DÉFINITION » (teinte de la matière), `.prop-box` « À RETENIR » (feuille + filet, gras d'ouverture à l'encre de la matière), `.notice` « À NOTER » (ambre, texte à l'encre normale, lisible en sombre), `.method-box` (titre = gras d'ouverture en serif ; `<li><span class="step">Étape n.</span>…` → pastilles numérotées, « Étape n. » gardé pour les lecteurs d'écran) ; `.reveal` = bloc entier cliquable (`role=button`, pastille « Afficher ▾ »).
- **Figures** : SVG aux couleurs du thème (classes `.svg-*`, `.lab-*`) ; un schéma dont un libellé passerait sous 12 px reçoit une largeur minimale (`--svg-min`, `.lisible`) puis défile (`.defile`) ; tableaux neutralisés et défilants ; code en JetBrains Mono sans ligatures.
- **Exercices** : `.exo` en carte (en-tête « EXO 01 » + difficulté), `.diff` « ★ ★ ☆ » → `data-niveau="2"`, 3 barres + « Moyen » ; questions « Q1. » en retrait suspendu, `.exo-part`, `.exo-source` ; `.exo.concours` (liseré + puce « Concours PT ») ; outils en tête de l'onglet (`.exo-tools` : segmenté Tous / Facile / Moyen / Difficile, puce « Concours PT · n », effectif) qui masquent par la classe **`.filtre-masque`** (jamais `hidden` : l'impression garde tout) ; « Voir la solution » `.toggle-sol` (classe `.open`, `aria-expanded`, 44 px au doigt) et solution à filet vert + intitulé « CORRECTION ».

### Simulateurs (région SIMU, SPEC §5.5)

DOM inchangé et uniforme des 26 simulateurs canvas : `.sim-wrapper > h2, .lead, .mode-switch?, .regime-badge?, .sim-controls, canvas, .sim-info, .notice?`. Une **grille à zones nommées** (titre, lead, badge, mode, scene, reglages, info, note) place la courbe à gauche et les réglages à droite **sans toucher au HTML** ; au téléphone, la courbe d'abord (collante), puis les réglages. Hauteur de toile par `--h` (`#tr-canvas{ --h:560px; }`…, région SIMU). Le module CONTENU pose `--p` sur chaque `input[type=range]` (piste remplie) et ajoute un bouton « Valeurs par défaut » (valeurs d'origine du HTML). Badges de régime `.regime-badge.pseudo/.critique/.aperiodique` écrits en variables (plus d'overrides sombres). Courbe principale à l'encre du chapitre : **`__CVchap(canvas)`** (`--chap-vif`, repli `accent`) ; étiquette détourée lisible sur un tracé : `__texteDetoure(ctx, txt, x, y)` ; libellés des canvas **≥ 12 px** (`ctx.font`). Lorentz (SVG) : libellés 13 px à l'ordinateur, ≥ 12 px au téléphone.

## Formules : deux conventions distinctes

- **Cours / méthodes** : LaTeX via MathJax. Inline `\( … \)`, bloc `$$ … $$` (**pas** `\[ … \]`). Pas de « < » collé à une lettre dans une formule (lu comme une balise : `\lt`, contrôlé par `validate.py`). Pas de macro d'extension absente (`\cancel`, `\ce`, `physics`…). Éviter les longues formules en ligne : `$$` dans `.formula` (qui défile au besoin).
- **Flashcards** : **par défaut** en **caractères Unicode** (ex. `ω₀`, `√(LC)`, `e^(iθ)`, `ω_k`, `≤`, `∫`, `z̄`, `ü`). À l'affichage, `makeFlash` applique `flashPretty()` qui **repère les fragments mathématiques, les convertit en LaTeX (`flashConvertMath()` : `^(…)`, `_(…)`, `√(…)`, `{…}`, `cos`, `z̄`, `ü`, `²`/`ₙ`…) et les enrobe dans `\( … \)`** ; MathJax (appelé dans `show()`) les rend **dans la police du cours**. Le texte français reste hors maths. Une carte écrite directement en `\( … \)` est **admise** et laissée intacte (536 cartes : decks cst, cine, stat, slci, et 459 cartes des 26 decks de PT spé) ; dès qu'un champ contient `\(`, `flashPretty` le laisse **entier** à MathJax : y écrire alors toutes les formules en `\( … \)` — dans la chaîne JS, doubler l'antislash (`\\(`). ⚠️ Séparation maths/texte **heuristique** : une carte mêlant phrase et formule peut demander une réécriture directe en `\( … \)`. Une formule seule (ou qui termine la 1ʳᵉ phrase) en tête de réponse passe en bloc dans la fiche (`flashReponseHTML`).

## Flashcards

```js
const <prefix>Cards = [
  {q:"Question ?", a:"Réponse."},
  {q:"Loi d'Ohm ?", a:"U = R·I", cat:'form'},   // cat facultatif
  …
];
const <prefix>Flash = makeFlash(<prefix>Cards, '<prefix>',
  '<prefix>-flash-content', '<prefix>-flash-prog', '<prefix>-stats');
```

- 160 decks, 3 749 cartes. `makeFlash` (`grep -n 'function makeFlash'`) gère retournement / notation (à revoir / hésitant / acquis) / progression / Leitner ; il range le deck dans `window.FLASH_REGISTRY[prefix]` et l'instance dans `window.FLASH_INSTANCES[prefix]` (`flip, rate, prev, next, resetProgress, getProgress, reload, isFlipped`).
- Champ facultatif **`cat:'form'|'val'`** (851 cartes) : badge « Formule » / « Grandeur » de la fiche et filtre « Formules / Grandeurs usuelles » du quiz.
- **État et identifiants de cartes** (`grep -n 'ÉTAT DES FLASHCARDS'`) — **INTOUCHABLE** : `flash:<prefix>` reste un tableau d'états `{h,o,e,last,box,due}` **aligné par position** (Bilan, `srsCountDue`, quiz, badge, rail « Mes cartes » le lisent par index) ; `flashids:<prefix>` mémorise l'identifiant de chaque position, `flashCardIds(cards)` = `'Q|R'` (empreintes FNV-1a de la question et de la réponse). `flashLoadState(prefix, cards)` **réaligne l'état par identifiant** ; `flashSaveState(prefix, cards, state)` écrit toujours les deux clés ensemble. **Migration au chargement** : chaque `makeFlash` réécrit l'état si l'ordre ou les identifiants ont changé (état « hérité » sans identifiants : conservé par position). `rate()`/`getProgress()` relisent le Store, et `quizRate` appelle `FLASH_INSTANCES[prefix].reload()` : quiz et onglet Cartes ne s'écrasent plus. La refonte n'a rien changé à cet état (vérifié octet pour octet sur une session de notation scriptée).
- **Règle d'édition des decks** (règle exacte : en-tête de `flashLoadState`). **Sans perte** : ajouter/retirer/réordonner des cartes ; **toute retouche de texte** (question et/ou réponse, remplacement global compris) à longueur et ordre inchangés (repli par rang : jamais pire que l'ancien appariement par position), **sauf** pour une question présente en double dans le paquet (n'en retoucher qu'une copie par mise à jour) et une réponse passée d'une carte à une autre dont les questions sont aussi retouchées ; question reformulée, réponse inchangée, gardant son rang depuis sa voisine reconnue précédente **ou** suivante (même si cette voisine a été déplacée), ou entourée d'autant de cartes retirées que de cartes ajoutées. **Carte remise à zéro** : question retouchée hors de ces cas (réponse aussi changée alors que des cartes sont ajoutées/retirées entre ses voisines — sauf autant d'ajouts que de retraits, voir la contrepartie —, carte retouchée **et** déplacée, rang changé des deux côtés), ou ambiguïté (deux candidates de même réponse). **Contrepartie** : entre deux voisines reconnues, autant de cartes nouvelles/retouchées que de cartes disparues → celles dont la réponse ne désigne pas une seule entrée prennent l'entrée de même rang : une carte ajoutée (ou retouchée et déplacée) à la place d'une disparue hérite de son état, et une carte à question **et** réponse retouchées côtoyant un retrait + un ajout peut recevoir l'état de la carte retirée (et la carte ajoutée, le sien). Prévenir l'utilisateur. `flagged` : réaligné par question **et** réponse, puis question seule ; question introuvable : garde son index, orpheline (`i:-1`, listée mais ne marque aucune carte) si cet index est pris par un autre signalement.
- **Fiche de révision** (région REVISION, SPEC §5.4 ; « fiche bristol ») : `makeFlash` n'enrichit le DOM statique d'un deck qu'à son **premier affichage** (ResizeObserver partagé `window.__flashRO`, ou premier appel de l'API ; marqueur `data-fc` sur `.flash-wrapper` ; rien n'est construit au chargement pour les decks jamais ouverts — le chargement sur téléphone en a beaucoup gagné) : en-tête `.fc-head` (badges matière, « Formule » / « Grandeur », dernière note ; 🔊 pour l'anglais), face `.flash-side` (question `.fc-q` sur réglure calée sur `1lh`, retirée par `:has()` si fraction ou formule en bloc ; au verso, question en rappel + `.fc-sep` « Réponse » + `.fc-a` : une formule de tête passe en bloc via `flashReponseHTML`, réduite pour tenir par `flashAjusterFormules`), pied (aide selon le pointeur au recto ; au verso `.flash-course-link` « Voir dans le cours · §n », cible = `flashCible`, et `.flash-flag-btn` « Signaler »), `.review-nav` (‹ Précédente / Passer), puis **tout en bas** `.fc-reveal` « Afficher la réponse » au recto **ou** `.flash-controls` au verso seulement (`.is-verso` sur le wrapper), chaque note avec icône, échéance Leitner (`flashEcheance`, calculée sur une copie de l'état) et touche ; progression « Carte n / N », barre empilée, « k dues ». Icônes de la fiche (undo, skip, flip, play) dans le sprite statique. L'ordre des cartes reste tiré à la création (`buildOrder`). Le quiz reprend la même fiche (`#quiz-card.flash-card.quiz-card`, `data-mat` sur `#quiz-screen-question`, `.is-verso` sur la fiche, rappel `#quiz-question-rappel`).
- **Raccourcis des cartes** (gestionnaire unique, **les 160 decks**) : Espace = retourner, 1 / 2 / 3 = noter au verso (au recto : sans effet, et plus de changement d'onglet sur l'onglet Cartes), ← → ; garde : champ de saisie, fenêtre ouverte, focus hors du chapitre, Ctrl/Alt/Méta. ## PWA (installable + hors-ligne sur mobile)

- `manifest.webmanifest` (nom, icônes `icons/`, `display:standalone`, `theme_color`/`background_color` aux couleurs des jetons) + `sw.js`. Enregistré en fin de `<body>` (`grep -n 'serviceWorker.register'`), **uniquement en http/https** (pas en `file://`, où le hors-ligne reste assuré par les assets embarqués).
- `sw.js` précache la coquille (`PRECACHE`, 45 entrées, dont `vendor/fonts/polices.css` et les 14 woff2). **HTML en stale-while-revalidate** : le SW sert le `index.html` en cache, récupère le réseau en arrière-plan et **réécrit `'index.html'` dans le cache courant** → nouvelle page au lancement **suivant**, même sans bump, mais sans bannière. **Assets en cache-d'abord** : jamais rafraîchis sans bump.
- **Mise à jour** : pas de `skipWaiting()` automatique ; après un bump de `CACHE_VERSION`, le nouveau SW attend et une **bannière « Nouvelle version disponible — Recharger »** (`.maj-banniere`, un toast et non une barre) propose la MAJ (clic → `postMessage(SKIP_WAITING)` → activation : purge de tous les autres caches de l'origine + `clients.claim()` → `controllerchange` → reload). Re-vérification au retour sur l'app (`visibilitychange`, au plus 1×/min).
- ⚠️ **Bump OBLIGATOIRE** : à chaque commit **publié** modifiant un asset mis en cache (index.html inclus), **incrémenter `CACHE_VERSION`** en tête de `sw.js` (`ptsi-cache-vN` → `vN+1`) **dans le même commit** : bannière, rafraîchissement des assets, purge des anciens caches, cohérence HTML/assets. (Branches de travail `wip/…` : bump unique au moment de la publication.)
- Ajout/retrait d'un fichier de `vendor/` ou `icons/` → mettre à jour `PRECACHE` (la suite `pwa` vérifie que chaque fichier listé existe).
- **Anomalie connue** : **rechargement automatique à la 1ʳᵉ visite** (`clients.claim()` déclenche `controllerchange`, qui recharge sans vérifier qu'un SW contrôlait déjà la page). D'où, dans les tests, `serviceWorkers:'block'`.

## CSS : régions, jetons, thème

Une région plus bas l'emporte à spécificité égale : pour battre une règle d'une région plus bas, jouer sur la spécificité, pas déplacer la règle. Petit `<style>` hors du grand bloc : schémas des exos de cinématique (dans `#cine-exos`, CONTENU, en jetons). Propriétaires et historique : `docs/refonte/travail/regions.md`.

**Jetons** (région JETONS, copie du `tokens.css` de la refonte) : polices `--font-text|ui|code`, graisses `--w-*`, échelle fluide `--fs-*` (en rem : suit A / A+ / A++), interlignes `--lh-*`, mesure `--measure` (34 em), espacements `--sp-*`, rayons `--r-*`, ombres `--sh-*`, durées `--dur-1/2/3`, plans `--z-*`, gouttière `--gutter` (16 px au téléphone), cible `--tap` (44 px) ; neutres `--desk` (bureau), `--sheet` (feuille), `--sunk` (creux), `--raise` (menus), `--text`, `--text-2`, `--text-3`, `--line`, `--line-2`, `--field`, `--primary`/`--on-primary`, `--focus`, `--link`, `--hover`, `--press`, `--scrim`, `--selection` ; matières `--physique`, `--maths`, `--si`, `--info`, `--anglais` (+ `-fond`, `-vif`) ; sémantique `--rouge`, `--ambre`, `--vert` (+ `-fond`, `-vif`, `--rouge-plein`/`--on-rouge-plein` des compteurs), notation `--note-0/1/2/nv` ; décor `--marge`, `--reglure`, `--bristol`, `--mill-*`. **`data-mat="<matière>"`** (posé en JS sur chaque `.chapter`, chaque rangée `.mob-chap-row`, chaque `.chap-title-banner`, et sur les lignes de la recherche, du quiz, du Bilan…) définit l'encre du chapitre `--chap`, `--chap-fond`, `--chap-vif` (et `--def-*`, `--prop-*`, `--meth-*`, `--notice-*`, `--mill-*`) ; hors `data-mat`, `--chap` = encre 2. **Anciens noms gardés comme alias** (le contenu des chapitres les emploie) : `--ink`→`--text`, `--paper`→`--sheet`, `--paper-dark`→`--sunk`, `--accent`/`--accent-deep`→`--rouge`, `--accent2`→`--physique`, `--green`→`--vert`, `--amber`→`--ambre`, `--muted`→`--text-3`, `--grid`→`--line-2` (ce n'est plus un quadrillage : filet de tableau), `--border`→`--line-2` et `--surface`→`--sunk`, `--dom-*`→encre de la matière, `--radius-s/m/l`, `--shadow*`, `--read-scale`. Nouveau code : les nouveaux noms (jamais `--border`/`--surface`). Les blocs JETONS et BASE sont le socle : ne pas y redéfinir de jeton depuis une autre région (besoin local : propriété personnalisée dans sa région).

**Thème sombre** : `:root[data-theme="dark"]` (thème **effectif**) est le seul sélecteur du sombre pour les règles de composant (lu aussi par `getCanvasColors`/`__CV`). **Seule exception : le filet de sécurité des jetons** — le bloc sombre des jetons est recopié **à l'identique** sous `@media (prefers-color-scheme: dark)` pour `:root[data-theme-pref="auto"]` et `:root` sans attribut (avant le JS, maquettes) ; une préférence « Clair » n'est visée par aucun sélecteur et reste claire. Ne pas écrire d'autre `@media (prefers-color-scheme)` ; retoucher les deux copies ensemble. **Trois préférences** (clé `theme`) : Clair, Sombre, **Auto** (défaut : suit le réglage de l'appareil **en continu**, via `matchMedia`). Le petit script du `<head>` pose `data-theme-pref` **et** `data-theme="dark"` **avant le premier affichage** (plus de flash clair ; sans `data-theme-pref`, le filet de sécurité rendrait sombre un « Clair » sur appareil sombre), ainsi que `html.nav-replie`. Le module THÈME du grand script (`grep -n 'function applyTheme'`, **local** à une IIFE) porte la préférence dans `data-theme-pref`, aligne les deux `<meta name="theme-color">` (couleur de `--sheet` : #fffdf9 en clair, #191b20 en sombre, chacune pour son media système) sur une préférence explicite, coche le choix courant (`[data-theme-set]`, `aria-checked`), suit le système en mode Auto (et la mention « actuellement : clair/sombre ») et redessine le chapitre visible quand le thème effectif change. API : `window.__themePref()`, `window.__setTheme('light'|'dark'|'auto')`.

**Couleurs dans les simulateurs/schémas** : toujours les variables de thème (ou `getCanvasColors()` côté canvas), **jamais une couleur codée en dur** — sinon le contraste casse en sombre. Sur fond coloré, `var(--sheet)` plutôt que `#fff`. `getCanvasColors()` détecte le sombre par `data-theme="dark"` sur `<html>` (correctif B4) ; ses `muted` (= `--text-3`) et `grid` (= encre du thème à 8 % en clair, 12 % en sombre, via `__hexAlpha`) viennent des jetons. Côté canvas, préférer **`__CV()`** (cache de `getCanvasColors()` invalidé par un MutationObserver au changement de thème — sûr dans les boucles rAF), **`__CVA('accent', 0.4)`** pour une couleur avec alpha (au lieu d'un `rgba(...)` en dur) et **`__CVchap(canvas)`** pour l'encre du chapitre. Le dessin a été migré (reste : quelques rgba de la palette claire, les hex de Lorentz). Les encadrés des simulateurs (`.sim-controls`, `.sim-info`, `.regime-badge.*`) sont écrits en variables dans la région SIMU, valables dans les deux thèmes : une nouvelle variante de badge y reçoit des couleurs issues des jetons.
